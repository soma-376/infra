# 0020. 프론트엔드 실행 로그는 환경별 기간 동안 CloudWatch에 보관한다

## Status

Accepted — 새 프론트엔드 Terraform 범위에 한정한다. 기존 CDK의 로그 그룹 정책은 변경하지 않으며 운영 확정 정책 검토는 계속 필요하다.

## Context

AGENTS.md에서 로그 정책 결정을 위해 예약한 번호다. PROJ-216의 EC2/Fargate 컨테이너 진단을 위해
로그 그룹과 삭제·보존·권한 경계를 먼저 정한다. 기존 CDK ApplicationStack의 로그 정책까지
일괄 변경하는 것은 이번 프론트엔드 인프라 요청 범위에 포함되지 않는다.

## Decision

- 단일 frontend 컨테이너의 stdout/stderr를 환경별 `/ecs/soma-376-frontend-dev|prod`에 저장한다. 새 컨테이너 종류가 생기면 별도 로그 그룹을 검토한다.
- dev는 14일, prod는 30일 보존한다. 개발의 단기 재현과 운영의 최근 배포·장애 조사를 위한 초기 보존 창이다. 실제 로그량·조사 주기 측정으로 재검토한다.
- `skip_destroy = true`로 Terraform 실행 환경 삭제 시 로그 그룹을 남긴다. 이후 이벤트는 보존 기간에 따라 만료된다. 그룹 자체를 재사용할 때는 해당 상태로 import해야 하며 다른 도구가 공동 관리하지 않는다.
- CloudWatch의 기본 저장 암호화를 사용하며 customer managed KMS key는 추가하지 않는다. 규제·별도 키 접근통제 요구가 생기면 재검토한다.
- execution 역할은 해당 그룹의 스트림 생성/이벤트 쓰기만 갖고 CI plan/apply 역할에는 로그 본문 읽기 권한을 주지 않는다. 담당 운영자는 별도 읽기 권한으로 조사한다.
- 토큰·쿠키·BFF 키·사용자 입력 본문을 로그에 기록하지 않는 앱 계약을 유지한다. 보존 기간은 시크릿 유출 방지책을 대체하지 않는다.
- 장기 감사 보관, S3 export, 경보는 이번 구현에 포함하지 않는다. 감사 요구 또는 실제 장애·비용 자료가 생기면 접근권한·보존 기간·경보 담당자를 함께 다시 정한다.

## Alternatives Considered

- 무기한 보존: 비용과 개인정보 잔존 기간을 불필요하게 늘려 선택하지 않았다.
- 실행 환경과 함께 삭제: 배포 실패·환경 재구축 원인을 잃을 수 있어 선택하지 않았다.

## Consequences/Tradeoffs

### Positive

- 실행 환경 교체/삭제 뒤에도 정해진 기간의 진단 로그를 조회할 수 있다.
- 앱과 CI의 로그 권한을 분리하며 저장 기간을 제한한다.

### Negative

- 30일이 지난 운영 사건의 로그는 복구할 수 없다. 장기 감사 저장소가 아니다.
- 로그 그룹이 상태 밖에 남을 수 있어 재생성 시 import 또는 승인된 수동 정리가 필요하다.
- 초기 기간은 측정된 용량 추정치가 아니므로 실제 로그 발생량과 비용 검토가 필요하다.

## Follow-up

- 기존 CDK 14일/DESTROY 정책은 이번 결정에 의해 자동 변경되지 않는다. 해당 정책 전환은 별도 작업에서 배포·삭제 영향을 검토한다.
