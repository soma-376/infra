# 0000. 결정을 서술하는 평서문을 제목으로 쓴다.

## Status

`Proposed` · `Accepted` · `Superseded by [ADR NNNN](NNNN-슬러그.md)` 셋 중 하나를 쓴다.
상태 값은 이 셋뿐이다. `Deprecated` · `Rejected` 는 쓰지 않는다 —
탈락한 대안은 `Alternatives Considered` 가 담고, 대체 없이 죽는 결정은
"무엇을 제거한다" 는 새 ADR 이 담는다.

**줄의 첫 토큰이 반드시 이 셋 중 하나여야 한다.** 뒤에 오는 것은 전부 부연이며
괄호나 `—` 로 잇는다. 인덱스와 스킬이 상태를 읽을 때 첫 토큰만 보면 되게 하기 위한 규칙이다.

```text
Accepted
Accepted (MVP 한정)
Proposed (부분 미결 — 세부 절차 미정)
Superseded by [ADR 0012](0012-슬러그.md)
```

**부분 대체는 `Accepted` 로 시작한다.** 문서 대부분이 여전히 구속력을 가지는데 `Superseded` 로
시작하면 읽는 쪽이 통째로 버린다. 무엇이 대체됐고 무엇이 유효한지를 같은 줄에 적는다.

```text
Accepted — 부분 대체: [ADR 0012](0012-슬러그.md) 가 일부 결정을 대체한다. 나머지 결정은 유효하다.
```

**전체 대체만 `Superseded by` 로 시작한다.** 그때는 대체하는 ADR 의 Status 도 같은 커밋에서 고친다.

## Context

이 결정이 필요해진 배경을 쓴다. 어떤 제약이 이미 존재하는지, 무엇이 문제인지, 무엇을 전제로 하는지.
**결정하지 않으면 무슨 일이 일어나는가**까지 적는다. 코드나 문서를 근거로 삼았다면 파일 경로와 절 번호를 함께 남긴다.

여기서 결정을 미리 말하지 않는다. 사실만 적는다.

크로스레포 결정이라 허브에 쓰는 경우, **어느 레포들이 걸리는지**를 여기에 명시한다.

**작성 규칙**

- 섹션 순서는 위와 같다. *(선택)* 으로 표시한 절은 내용이 있을 때만 둔다.
- **취소선(`~~…~~`)은 문서 어디에서도 쓰지 않는다** — Follow-up 만이 아니라 Decision·Consequences 도.
  무엇이 왜 닫혔는지가 남지 않고, 취소선 텍스트는 grep 에 그대로 걸려 렌더링하지 않는 도구에게
  죽은 결정이 살아 있는 것으로 보인다. 대체된 서술은 `**대체됨(ADR NNNN)** —` 접두 표기로 남긴다.
- **인용에 행 번호를 쓰지 않는다.** 코드·문서를 근거로 삼을 때는 절 번호, 함수·상수·구조체 이름,
  또는 인용문 자체로 가리킨다. 행 번호 정합은 검증할 방법이 없어 반드시 낡는다.
- **작성일은 문서에 적지 않는다.** `git log --follow <파일>` 로 확인한다.
- 번호는 그 레포의 다음 미사용 번호를 쓴다. 첫 ADR 은 `0001` 이다.
- 파일명은 그 레포의 슬러그 관례를 따른다 — **infra·허브(`soma-376/docs`)는 영어,
  `pulsemetry-backend`·`telemetryctl`·`ai-telemetry-pipeline` 은 한국어 슬러그**다. 레포끼리 통일하지 않는다.
- 새 ADR 을 추가하거나 기존 ADR 의 Status 를 바꾸면 **같은 커밋에서** 그 레포 ADR 인덱스(README)의
  표를 갱신한다. 인덱스가 파일 목록과 어긋나는 커밋은 만들지 않는다.
- 다른 레포의 코드·계약에 걸리는 결정은 단일 레포가 아니라 **문서 허브(`soma-376/docs`)의 `adr/`** 에 쓴다.
  판단이 애매하면 이렇게 묻는다 — *"이 결정을 뒤집으려면 몇 개 레포의 PR 이 필요한가."* 둘 이상이면 허브다.
  토큰 해시 방식·`enrollment` 스키마 소유·신원 전파 배선·계약 스키마 파일(`contracts/*.schema.json` 등)의
  변경은 거의 항상 허브 ADR 이다.
